# 1TXT 桌面端 — 安装版（NSIS）与解压版（ZIP）打包指南

> 1TXT 桌面端基于 Electron + electron-builder。Windows 下我们提供两种发行形态，**两种可以并存于同一台机器**，且默认配置一次构建即可同时产出两份产物。

---

## 1. 一句话区别

| 维度 | 解压版（ZIP） | 安装版（NSIS） |
|------|--------------|----------------|
| 产物文件 | `1TXT-1.0.0-win-x64.zip` | `1TXT-Setup-1.0.0-x64.exe` |
| 大小（参考） | ~163 MB | ~95 MB（NSIS 自带 LZMA 压缩，体积更小） |
| 安装过程 | 解压即用，无任何写入注册表/开始菜单 | 走安装向导，写注册表、创建快捷方式 |
| 启动速度 | **秒开** | **秒开**（两者都是直接启动，不需要解压临时文件） |
| 数据存放位置 | EXE 同级 `1txt-data\` 目录 | `%APPDATA%\1TXT\` |
| 卸载方式 | 删整个文件夹 | 控制面板 → 程序和功能 |
| 更新方式 | 重下载新 zip 覆盖（数据不丢） | 安装新版覆盖（或自动更新） |
| 适合人群 | 想试用 / 不想留痕 / 需要 U 盘携带 | 长期使用 / 想要桌面快捷方式 / 系统级集成 |
| 跨机器迁移 | 整个文件夹拷过去即可（含数据 & 登录态） | 只能装新机器后重新登录同步 |

## 2. 一次构建，两个产物（推荐）

`electron-builder.json` 已经把两种 target 同时挂在 `win.target` 数组里：

```json:48:62:electron-builder.json
  "win": {
    "icon": "resources/images/simplenote.ico",
    "artifactName": "1TXT-${version}-win-${arch}.${ext}",
    "target": [
      {
        "target": "zip",
        "arch": ["x64"]
      },
      {
        "target": "nsis",
        "arch": ["x64"]
      }
    ]
  },
```

执行：

```powershell
npm run build:win
```

构建完成后，`release\` 目录会同时出现两个文件：

```
release\
├── 1TXT-1.0.0-win-x64.zip          ← 解压版
└── 1TXT-Setup-1.0.0-x64.exe        ← 安装版
```

---

## 3. 只想要其中一种？

我们也提供了细分脚本（在 `package.json` 的 `scripts` 里）：

```bash
# 只产解压版（zip）
npm run build:win:zip

# 只产安装版（NSIS exe）
npm run build:win:nsis
```

它们的本质是给 `electron-builder` 命令加上 target 名做白名单过滤，不会改 `electron-builder.json`。

## 4. 如果 release/ 目录被锁住打不开

Windows 上偶尔会遇到 IDE/杀毒软件（典型：腾讯电脑管家、360、Windows Defender 实时防护）锁住上一次打包出来的 `app.asar`，导致新构建无法清理旧目录，报 `EBUSY: resource busy or locked`。

处理顺序（从快到慢）：

1. **关掉正在运行的 1TXT.exe**——如果你在 `release\win-unpacked\` 双击试运行过，先把它关掉。
2. **临时关闭杀毒软件的实时防护**（仅几分钟）→ 重新 `npm run build:win`。
3. **重启 Cursor / 重启电脑**——最稳妥，10 秒回归正常。
4. 实在不想重启，可以**单独把 `release/` 改个名**（重命名父目录 Windows 偶尔放行），再让 electron-builder 写新的 `release/`。

## 5. 工作流自查（开发阶段最快迭代）

只想验证启动效果、不需要打包成 zip/exe 的时候用 `pack:win`，跳过压缩步骤：

```powershell
npm run pack:win
```

产物在 `release\win-unpacked\1TXT.exe`，双击秒开。这是最快的迭代方式。

## 6. 两种版本在用户机器上的"共存"机制

> 这是文档最关键的一节，因为很多人会担心：装机版和解压版会不会抢同一份数据？答案是 **不会**。

`desktop/app.js` 启动时会做一次"绿色版判断"，决定 Electron 的 `userData` 落到哪儿：

```javascript:26:51:desktop/app.js
// --- Portable / "green" mode: redirect userData next to the EXE ---
const SYSTEM_INSTALL_PATTERNS = [
  /\\Program Files( \(x86\))?\\/i,
  /\\WindowsApps\\/i,
  /\\AppData\\Local\\Programs\\/i,
  /^\/Applications\//,
  /^\/usr\//,
  /^\/opt\//,
];

if (app.isPackaged) {
  const exeDir = path.dirname(app.getPath('exe'));
  const isSystemInstall = SYSTEM_INSTALL_PATTERNS.some((re) => re.test(exeDir));
  if (!isSystemInstall) {
    const portableUserData = path.join(exeDir, '1txt-data');
    app.setPath('userData', portableUserData);
    app.setPath('appData', portableUserData);
    app.setPath('logs', path.join(portableUserData, 'logs'));
  }
}
```

判定结果：

| EXE 实际所在路径 | 判定 | 数据落地位置 |
|------------------|------|------------|
| `D:\Tools\1TXT\1TXT.exe`（用户解压到任意目录） | **解压版** | `D:\Tools\1TXT\1txt-data\` |
| `C:\Users\xxx\AppData\Local\Programs\1TXT\1TXT.exe`（NSIS 默认 perMachine=false） | **安装版** | `%APPDATA%\1TXT\` |
| `C:\Program Files\1TXT\1TXT.exe`（perMachine=true 时） | **安装版** | `%APPDATA%\1TXT\` |
| 开发模式 `npm run dev` | **dev**（`app.isPackaged=false`） | `%APPDATA%\1TXT\` |

### 共存意味着什么？

如果用户**同时**装了 NSIS 安装版和拷了一份解压版到 D 盘：

- 两份程序**完全独立**，分别有自己的 `userData`
- 等价于"两个独立账号"——可以各自登录不同 Supabase 邮箱试用
- 笔记数据互不可见、互不同步（除非两份都登同一个 Supabase 账号，那就通过云端同步）

> 如果你不希望两份共存出现"数据看起来不一致"的疑惑，**只装其中一种**即可。我们推荐先用解压版试用 1~2 周，确定要长期用了再换装机版。

## 7. 体积优化建议（可选）

当前体积参考（`1.0.0`）：

| 产物 | 大小 |
|------|------|
| ZIP | ~163 MB |
| NSIS EXE | ~95 MB |
| 解压后实际占用 | ~280 MB（Electron 框架 + Chromium + node_modules） |

如果未来想进一步压缩：

1. **去掉未用的 dependencies**：`monaco-editor` 占了 ~30 MB，1TXT 主要用 Vditor，可以考虑只 dev 时引入，运行时 lazy load
2. **electron-builder 加压缩等级**：在 `electron-builder.json` 加 `"compression": "maximum"`（已经是默认 normal，maximum 能再省 5-10%，但打包时间翻倍）
3. **删除未用的 locales**：`asar` 内 `dist/locales/` 里有几十种语言的 i18n 文件，可以加 `electronLanguages: ["en-US", "zh-CN"]` 只保留需要的

这些都是"想再优化时"的备选项，不影响正常发布。

## 8. 常见问题

**Q：为什么 ZIP 比 NSIS 大那么多？**
A：NSIS 用 LZMA 算法压缩，效率更高；ZIP 用 deflate 算法，跨平台兼容更好但压缩比差。两者解压后内容完全相同。

**Q：可以让解压版跟安装版数据互通吗？**
A：可以，但不推荐。把 `desktop/app.js` 里的判断逻辑去掉就行（让两种都走 `%APPDATA%\1TXT`）。但这样解压版就失去了"绿色"特性，整个文件夹搬走数据会丢。建议**通过 Supabase 云端同步**实现跨设备一致。

**Q：用户装了安装版，再下载解压版打开，会冲突吗？**
A：不会。两边完全独立运行，可以同时打开两个窗口（分别登不同账号也行）。如果同登一个账号，二者都会通过 Supabase Realtime 实时收到对方的笔记修改。

**Q：发布到 GitHub Releases 应该传哪个？**
A：**两个都传**。在 Release 页用文字引导用户：
> - 想装一下、设置开机启动、留桌面快捷方式 → 下载 `1TXT-Setup-1.0.0-x64.exe`
> - 想试用 / 用 U 盘携带 / 单位电脑无安装权限 → 下载 `1TXT-1.0.0-win-x64.zip`
